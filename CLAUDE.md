# Bridge — Project Instructions

Bridge = **Living Software** — software that builds itself around your work. Adaptive workspace platform (Kernel → Compiler → Runtime → Generated Workspace) for professionals + teams; learns how the user works, generates the workspace, continuously evolves workflows/skills/agents/tools. NOT a CRM, sales tool, task manager, or static app of any category. Core principle: **everything is proposed, governed, and continuously evolved** (Capability Lifecycle Platform). **Multi-surface (Notion model)**: one surface-agnostic kernel, three thin clients — web + desktop (Tauri) + mobile; desktop built first (sequencing only, not an architecture constraint). First compiled workspaces ship as **mix-and-match add-on capability packages** (DealPilot, Helpdesk, Recon — Pi-extensions model, NOT separate products; ADR-018/020). **Universal Commons** = cloud registry of generalized capability knowledge only (never user data); v1 = curated package registry; control-plane sync lives in a separate "Bridge Cloud" service. **Integration over custom development**: Learning Agent checks installed software/browser apps (explicit permission, stated intent) and proposes integration before building; from-scratch = open-source-based fallback option. Competitors: ambient desktop agents (Vida, Invoko, AirJelly) · generated/flexible workspaces (Notion AI, Fibery, Noloco) · agent-ops platforms (Retrace, AgentOS) — never framed against OS vendors. Per-product competitors (e.g. DealPilot's) are researched live by the Learning Agent at blueprint time, never hardcoded. Vision + full re-audit of prior decisions: [docs/wiki/vision.md](docs/wiki/vision.md). Full context: [docs/wiki/index.md](docs/wiki/index.md).

## Working rules
- **Search for relevant skills BEFORE heavy actions.**
- Keep docs current; log changes in `docs/log.md`.
- **Record decisions with rationale.** Non-trivial engineering call → append an ADR entry to [docs/raw/decisions-log.md](docs/raw/decisions-log.md) (decision · why · alternatives rejected · consequences). Locked strategic one-liners still go to [docs/wiki/decisions.md](docs/wiki/decisions.md).
- **File bugs/abnormalities the moment you spot them**, without waiting to be asked → add a row to [docs/BUGS.md](docs/BUGS.md) (OPEN/IN PROGRESS/RESOLVED). Fixing one → mark RESOLVED + date.
- **Blast-radius scan before finishing.** You own the neighbourhood, not just the file. Before declaring work done, check the features/modules your change touches or borders (callers, shared types, sibling skills/adapters, the pipeline/gate, the prototype surface) and confirm they still hold. Anything off → fix in scope, or log to known-issues / raise a background-task chip if out of scope. Never report green on a narrow check that ignored what the change could break.
- **Vocabulary — two scopes (pivot 2026-07-06)**: KERNEL scope (packages/core/api/governance/docs) = Bridge vocab: Person / Relationship / Memory / Community / Initiative / Ritual / Touchpoint / Signal — never Lead / Pipeline / Contact. WORKSPACE scope (compiled products like DealPilot, generated vocabularies) = domain vocab allowed; generated vocab aligns to Bridge theme by default; user's own naming always wins. ESLint `bridge/no-crm-vocab` re-scoped (2026-07-06) to kernel paths only (`packages/*/**`, `apps/api/**`), enforced inside the rule via `context.filename` — not in `eslint.config.js` (protected file).
- **NO dummy data (REVERSED 2026-07-06 — was "dummy_-prefix everything")**: the platform shows real, connected data only. Do not create new seeded/demo/placeholder product state. Existing `dummy_`-prefixed instances are tracked debt (see [docs/BUGS.md](docs/BUGS.md)), not to be treated as an ongoing pattern. Unit-test fixture literals are a separate, still-open question — do not assume this rule extends to them without asking.
- **Principles**: adapt before asking · learn before acting · explain before automating · govern before executing · build only what creates lasting value · simple surface, powerful underneath. Retained from pre-pivot: trust-first (private default, both-party consent) · governed agentic execution (explainable, permissioned, auditable — draft-then-approve generalized into the Capability Trust Model: risk computed from manifests, trust-based approvals, External band always human at launch) · ambient AI · action over analytics (every Signal → an action). Capture contract: every capture → inspectable Memory entry; avatar blink = the tell; raw capture local-plane only.

## Stack (see [docs/wiki/stack.md](docs/wiki/stack.md))
TS monorepo: React+Vite+tRPC+Fastify+Drizzle+Supabase (pgvector+pg_trgm+RLS). Kernel is surface-agnostic; **web + desktop (Tauri) + mobile = three thin clients over one API** (Notion model) — desktop shell built first (Rust capture core = P0), apps/web hosted inside it and independently reachable, mobile later. Sensor SPI (desktop capture/system events/browser) = an optional capability, desktop-only, never a kernel dependency. Models: `ModelProvider` seam (Ollama dev, configurable prod, Claude default; capture/sensor plane = local models default). Runtime: thin custom (Agno + LangGraph patterns), Hatchet ritual engine, BullMQ; adopt **Mastra components (evals/workflows) + Mem0 (memory)** behind ports, local-plane compatible. Defer Temporal behind `RitualExecutor`.
