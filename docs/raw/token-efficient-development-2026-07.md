# Token-Efficient Development

Goal: make future development cheap in tokens without losing fidelity. Bridge already has strong
bones for this (the wiki/raw caveman protocol, `docs/CODEMAPS/*` with per-file token estimates,
the `update-codemaps` skill). This doc audits what exists, prescribes the missing artifacts, codifies
best practices, and gives a roadmap.

## 1. What already works (keep + extend)
- **Two-tier docs (wiki caveman / raw full).** The single biggest token lever: an agent reads a
  ~40-line wiki page instead of a 300-line raw doc 90% of the time. Every `docs/wiki/*.md` is under
  ~165 lines. **This is the model to defend** — the config-alignment audit found harness noise
  (superpowers mandate, ~300 irrelevant skills) is the main thing eroding it.
- **CODEMAPS with token estimates.** `docs/CODEMAPS/{architecture,backend,data,frontend,dependencies}.md`
  each carry a `Token estimate: ~N` header and a "Files scanned" provenance line. ~650 tokens gets an
  agent the whole architecture. Regenerated by the `update-codemaps` skill.
- **CLAUDE.md as the single contract**, now that the stale root `AGENTS.md` is neutralized (a second
  drifting instruction file was pure token+confusion cost).

## 2. New artifacts to build (ranked by token-saved-per-effort)
1. **A repo `INDEX.md` / navigation map (highest leverage).** One ≤50-line "where does X live" table:
   primitive → package → key file. Today an agent greps to find `authority.ts`/`pipeline.ts`; a
   pointer table removes those exploratory reads. Generate from CODEMAPS.
2. **Symbol/interface index per package** (`docs/CODEMAPS/symbols.md`): the public exports + one-line
   contract for each of `packages/{core,db,local,models,sensors,...}`. Lets an agent wire against a
   port without reading its implementation. Auto-generated from `index.ts` exports + TSDoc.
3. **Sequence diagrams for the 3 load-bearing flows** (mermaid, text-diffable, cheap to read):
   `action.propose→decide` pipeline, the plane gate crossing, and ritual planner→executor. One diagram
   replaces re-reading `pipeline.ts`+`authority.ts` each session. Store in `docs/CODEMAPS/flows.md`.
4. **A schema ER sketch** (mermaid) over `SCHEMA.sql` — the table graph + the two-plane split — so
   data questions don't require reading 400 lines of SQL.
5. **Per-package `AGENTS`-style header comments** (already partly present, e.g. `client.ts` doc block):
   a 3-line "what this package is / its ports / its invariants" at the top of each `index.ts`. Cheapest
   possible context, read for free when the file is opened.
6. **A "capability manifest cheat-sheet"** — the one schema an agent needs most when adding a
   capability, extracted from the (currently untyped) manifest JSONB once EVAL/undefined-elements work
   types it.

## 3. Token best practices (make these standing rules)
- **Read wiki before raw; raw before code; code last.** Escalate only on strong need. (Already the
  protocol — enforce via CLAUDE.md + a project `.claude/settings.json`.)
- **Delegate fan-out searches to subagents** (Explore/general-purpose): a subagent burns its own
  context reading many files and returns the conclusion, keeping the main thread lean. This session's
  audits are the pattern.
- **Prefer the dedicated file tools over `cat`/`sed`/`grep` dumps**; request specific line ranges.
- **Keep append-only ledgers (log.md, BUGS.md) out of default reads** — they're 800–1300 lines; link,
  don't load. Consider quarterly rotation of `log.md` into `log-archive/` to cap its size.
- **Cache-friendly cadence**: batch independent tool calls in one turn; avoid re-reading a file you
  just edited (the harness tracks state). Long idle waits past 5 min cost a cache miss.
- **Regenerate codemaps on structural change, not every commit** — stale is cheaper than churn, and
  the provenance header shows staleness.
- **One instruction source of truth** (CLAUDE.md). Every extra always-loaded instruction file or
  always-on skill mandate is a per-turn tax.
- **Scope the harness**: disable the ~300 off-project skills (see `skills-diluting-project.csv`) — they
  inflate the tool-search space and every skill-selection decision.

## 4. Roadmap
- **Now (Month 1, with DOCS-1)**: build INDEX.md nav map + the 3 flow diagrams + schema ER sketch;
  add the standing token rules to CLAUDE.md; land the project `.claude/settings.json` that scopes skills.
- **Month 2**: auto-generated symbol/interface index; per-package `index.ts` header contracts; wire a
  `pnpm docs:codemaps` script so regeneration is one command; add a "token estimate" line to every raw
  doc (like the codemaps already have).
- **Month 3**: capability-manifest cheat-sheet (after the manifest schema is typed); log.md rotation;
  a lint/CI check that flags a wiki page >1000 lines (protocol auto-enforcement) and a raw doc missing
  frontmatter.
- **Ongoing**: keep the wiki caveman-terse; treat any new always-loaded context as a reviewed cost.

## 5. Measure it
Track a rough "tokens-to-orient" proxy: the sum of (CLAUDE.md + wiki/index + the smallest set of pages
an agent must read to start a typical task). Target: a new task should be startable from < ~4k tokens of
docs before touching code. The codemaps' own token-estimate headers are the unit; extend the habit to
wiki pages.
