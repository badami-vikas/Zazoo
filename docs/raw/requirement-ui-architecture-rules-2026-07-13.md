Encode the following rules into the repo and ensure the first task on next run aligns the project with these rules.

While taking decisions and unsure, I want you to run a deeper codebase analysis of relevant open source repos.  I want them to find all relevant functions, objects and structure we can learn from. If the doesnt help ask questions to user.

If underlying data is highly related (different columns of same table), like people, communities or Automations, Agents, skills, and iIntegrations or Deals, Sources, and Thesis, then it should become toggle at top. Each toggle page is simple referred to as page.

Each section within a page is called section. Unless explicitly specified, all pages have the standard views (table, card, etc) as landing section followed by other related sections that appear below it. The landing section can be internally scrollable as well. Further scrolling will scroll the page. Move the control panel option into 3 dots and reconsider what goes into it and what appears as sub sections. 

If underlying data is same columns of same table, then it should appear as lists.

If underlying data is related to same module but not strongly related to root module or any current sub-modules, create a new sub module. A sub module will appear as collapsible and expandable dropdown in left nav bar from module

Also add forum as a standard view option where instead of presenting existing data, the form collects data related to every field. 

Inside Documents, create "Bridge Workspace" folder with Each module having a dedicated folder inside it. Each sub module has a dedicated folder inside module. All artefacts and accumulated data that is stored locally is stored in this folder. Also below the landing section, show artifacts section where I can see all artefacts generated by the module. If too many (more than 20), organise them into sub folders

Once done, realign all the plans in priority, with priority on getting the prototype of egg and commons developed first, followed by cleaning repo removing duplicates and depreciated data and finally fixing bugs. Rest of the implementation should be placed next. Also git pull before you proceed with planned implementation for there might be additional work done by my developer. If you have an alternative priority recommendation, recommend.

List everything I'm missing in above prompt

Ask as many clarifying questions as needed.

Once done, commit, push and merge to main
