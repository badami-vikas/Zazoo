## Practice hardening (2026-07-06 research sweep — folded into phases below)
- **P0**: lethal-trifecta policy rule (private-read + untrusted-ingest + egress ⇒ auto-External band, overrides computed risk) · ≤20 active tools per agent turn, deferred registry lookup beyond · sensing = CONTEXT PROVIDER registry (9 kinds, raw/derived split at type level) not 3 sensor kinds · approval = durable resumable state (zero-compute wait, engine signal/wait primitives), never poll.
- **P1**: onboarding = pop-up screen · blueprint = persisted draft + diff + approval card (NO competitor ships pre-apply approval — Notion/Fibery/Noloco all post-hoc undo — this is the moat).
- **P3**: **two-gate promotion** for every generated capability (output-quality pass rate + trigger precision/recall, independent) · Draft→Validated = success threshold on originating tasks + generalization test on novel tasks (MUSE-Autoskill) · held-out eval selection (no overfitting own evals) · baseline-vs-with-capability parallel runs = default eval · self-critique loop (post-run log friction → rewrite proposals) · description-tuning = own subsystem w/ human-approved trigger eval set · **dry-run + per-step approval gates = SHIP** (no builder has them) · Mastra live-eval sampling = heartbeats · red-team assertion pack gates External-band validation.
- **P4**: Voice Command Center = cross-surface (desktop/browser/mobile, per-platform capability subsets) · browser→desktop delegation (privileged native ops via `delegations` + ephemeral grants, through pipeline).
- **P5**: capability versioning = Zapier-style single-live + auto-demote-prior-to-available · rollback = fork-from-history, never in-place revert (append-only) · in-flight runs survive capability revision via version markers/step memoization.
- Agents (all phases): star topology — Chief of Staff sole router, NO peer handoffs · hard chain-depth cap + best-so-far fallback · per-agent memory file w/ size ceiling · autonomy ramps DOWN from 100% review (CrewAI 2B-workflow evidence).

## Optimizations + Memory-lifecycle + VM-isolation ingest (2026-07-14, AP-007 — ADD-ONs to phases, NOT a batch reorder; verbatim proposal: [../raw/optimizations-memory-vm-dealpilot-plan-2026-07.md](../raw/optimizations-memory-vm-dealpilot-plan-2026-07.md) §2/§4/§6)
- **P0**: **O0 observability** (token/cost/latency attribution, prompt receipts, per-run budgets) · **Memory retrieval/security lifecycle** (local secret+injection scan → classify episodic/semantic/procedural/preference/failure/correction → dedupe/conflict → policy-only retrieval fenced with source/confidence/age → immediate correction capture → pre-compaction/shutdown flush; memory is context never instruction, current user/repo/policy wins) · **execution-target policy types** + CredentialBroker allow/deny account constraints + audit-proof of the selected account/profile (`least_isolated_target_that_proves_policy_and_safety`).
- **P0–P3 runtime taint RT0–RT4 (root-gap closure)**: RT0 label+lattice+required runtime envelope → RT1 propagation through retrieval/prompt/model/Skill/Action/Event/Result/File and queues/caches/retries → RT2 complete source/sink instrumentation with unknown labels fail-closed → RT3 quarantine + joined-label egress/tool policy, declassification only by deterministic validator or explicit Human Decision → RT4 backfill, trace UI, metrics, replay, compatibility removal. Metadata tagging alone is NOT completion; high-autonomy research/MCP/ambient paths stay gated until RT3.
- **P1**: **O1 lossless compression** (HTML/JSON/log/tool-output transforms, dedupe, anchors, cache) · **O2 retrieval-first context** (policy-only memory, hot-context selection, deferred tool/package disclosure — extends the ≤20-tools rule).
- **P2**: **O3 semantic compression** (model summaries with source anchors + quality gates).
- **P3**: **O4 adaptive optimizer** (per-capability policies learned from evals, governed proposals only) · **container/microVM SandboxProvider** for Capability Builder + untrusted execution (snapshot, quota, network-off-default, teardown — Open-Computer patterns behind the port, no embed until license/maturity gates pass).
- **P4**: **optional visible Isolated Computer package** for cross-app desktop work (human observe/intervene/ask-user).
- **P6**: **tenant-dedicated + remote compute pools** if demand justifies operations.
- **Order preserved**: no six-month batch reorder — these schedule into phases only as their dependencies/security gates clear (security P0 · runtime taint · durable package store · MemoryEngine port · token/eval telemetry · CredentialBroker · SandboxProvider). Recommended intra-phase rank in §6; benchmark memory before claiming superiority (recall@k, stale-memory rate, correction carryover, secret-block rate, tokens/answer).
