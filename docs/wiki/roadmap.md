## Practice hardening (2026-07-06 research sweep — folded into phases below)
- **P0**: lethal-trifecta policy rule (private-read + untrusted-ingest + egress ⇒ auto-External band) · ≤20 disclosed Agent capabilities per turn, deferred registry lookup beyond · Context Provider registry (raw/derived split) · durable resumable approval state, never poll.
- **P1**: onboarding = pop-up screen · blueprint = persisted draft + diff + approval card (NO competitor ships pre-apply approval — Notion/Fibery/Noloco all post-hoc undo — this is the moat).
- **P3**: **two-gate promotion** for every generated capability (output-quality pass rate + trigger precision/recall, independent) · Draft→Validated = success threshold on originating tasks + generalization test on novel tasks (MUSE-Autoskill) · held-out eval selection (no overfitting own evals) · baseline-vs-with-capability parallel runs = default eval · self-critique loop (post-run log friction → rewrite proposals) · description-tuning = own subsystem w/ human-approved trigger eval set · **dry-run + per-step approval gates = SHIP** (no builder has them) · Mastra live-eval sampling = heartbeats · red-team assertion pack gates External-band validation.
- **P4**: Voice Command Center = cross-surface (desktop/browser/mobile, per-platform capability subsets) · browser→desktop delegation (privileged native ops via `delegations` + ephemeral grants, through pipeline).
- **P5**: capability versioning = Zapier-style single-live + auto-demote-prior-to-available · rollback = fork-from-history, never in-place revert (append-only) · in-flight runs survive capability revision via version markers/step memoization.
- Agents (all phases): star topology — Chief of Staff sole router, NO peer handoffs · hard chain-depth cap + best-so-far fallback · per-agent memory file w/ size ceiling · autonomy ramps DOWN from 100% review (CrewAI 2B-workflow evidence).

## External agent access EA0–EA5 (2026-08-06, AP-114/ADR-194 — ADD-ONs to phases, NOT a reorder; full: [../raw/external-agent-access-plan-2026-08.md](../raw/external-agent-access-plan-2026-08.md) · wiki: [external-agents](external-agents.md))

Letting Claude Code / any MCP client build Modules, Databases, Skills and Automations for a Bridge installation. **PLAN ONLY — nothing built, no TASK rows until a slice is pulled forward through APPROVALS.** Governing sentences: *structurally absent, not policy-denied* · *introducing a new state is a human decision, returning to an old one is not* · *restore restores the document, not the world*.

- **REFER FIRST — Avilo Advisory** shipped substantially this design (`docs/wiki/mcp.md`, `AGENTS.md`, ADR-041/042/043/044) and corrected four things: transport determines the security requirement (stdio needs no auth) · isolation belongs in the import graph, not a helper call · restore/propose asymmetry (Bridge had the append-only substrate, not the permission conclusion) · the sandbox recommendation was overbuilt. Read it before EA0.
- **P0/security track**: **EA1 import-graph isolation test** — walk transitive imports from the gateway entry, fail on any reachable first-party file naming a personal-data table, exclude data-path modules by name, and **fail if the walker resolves too few files** (vacuity guard); verify by deliberately breaking it. Cheap, independent of EA0 shipping.
- **P1**: **EA0 local stdio gateway** — six tools (describe_surface · get_configuration · list_versions · get_version · propose_change · restore_version), no `activate`/`approve`/egress tool in existence. Gateway is a client of Bridge's own governed pipeline, never a second reader of the store. Distinct `mcp:external-agent` principal visible in history; validation errors returned to the agent for self-correction; unknown id ⇒ whole document refused. **Blocking dependency, unverified: whether a configuration version ledger exists today** — propose-only ships without it, history/restore tools do not. Does **not** depend on the H1 auth fix (stdio crosses no network boundary); H1 stays a blocker for the product and for EA3.
- **P1–P2**: **EA2 restore + Bridge qualifier** — unattended restore only when references still resolve identically and no referenced capability's trust band or credential grant has moved; otherwise it degrades to a proposal. External restores notified + rate-limited. Adopts the four history properties unchanged (single writer · forward-only · normalized not delta · baselined).
- **P3**: **EA4 shrink the code-bearing surface** (folds into BA0/BA1, adds no slice) — make the View/Database/Page/layout schema structurally incapable of holding code or markup so that surface needs no sandbox; keep the BA0 sandbox strictly for capability bodies that execute. Standing rule: **a sandbox must never become the justification for a looser schema.** Revisit trigger: if the component registry ever admits a type carrying executable or markup content, the sandbox becomes mandatory there.
- **P3+, conditional**: **EA3 networked gateway** — only if a non-stdio transport is ever wanted, and then H1 auth + scoped expiring tokens + `untrusted_external` taint labeling are required **before** that transport ships. Bridge keeps its taint lattice where a single-door app would correctly defer one (several differently-trusted sources flow into each other here: email, capture, scrape, Commons, MCP, external agents).
- **EA5 agent-legible surface + dev-time** (P2 for the machinery, ecosystem push P6/deferred): `AGENTS.md` inside the installed build, with live `describe_surface` as the primary contract and any published document explicitly secondary. Dev-time governance protection = tests that always run (isolation guard · an assertion that fails if an `activate`-shaped tool ever appears · forward-only history tests), not CODEOWNERS, which presumes multiple humans. **Publishing an installable authoring skill / treating the capability grammar as an ecosystem play is DEFERRED** — premature at one user; the machinery makes it possible later.
- **Vendo demoted to pattern source only** ([runvendo/vendo](https://github.com/runvendo/vendo), Apache-2.0): converges usefully (single choke point, constrained generation format, approval-gated tools, opt-in MCP door) but has no taint, no residency planes, no versioned capability lifecycle — it retrofits adaptability onto static products, which Bridge is natively. Joins bolt.diy/Dyad/Budibase/Appsmith/ToolJet as a sixth pattern source; **no reuse intake required** unless a specific import is later proposed; never run its guard as a second governance plane beside Bridge's authority plane.
