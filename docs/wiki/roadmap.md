## Practice hardening (2026-07-06 research sweep — folded into phases below)
- **P0**: lethal-trifecta policy rule (private-read + untrusted-ingest + egress ⇒ auto-External band, overrides computed risk) · ≤20 active tools per agent turn, deferred registry lookup beyond · sensing = CONTEXT PROVIDER registry (9 kinds, raw/derived split at type level) not 3 sensor kinds · approval = durable resumable state (zero-compute wait, engine signal/wait primitives), never poll.
- **P1**: onboarding = pop-up screen · blueprint = persisted draft + diff + approval card (NO competitor ships pre-apply approval — Notion/Fibery/Noloco all post-hoc undo — this is the moat).
- **P3**: **two-gate promotion** for every generated capability (output-quality pass rate + trigger precision/recall, independent) · Draft→Validated = success threshold on originating tasks + generalization test on novel tasks (MUSE-Autoskill) · held-out eval selection (no overfitting own evals) · baseline-vs-with-capability parallel runs = default eval · self-critique loop (post-run log friction → rewrite proposals) · description-tuning = own subsystem w/ human-approved trigger eval set · **dry-run + per-step approval gates = SHIP** (no builder has them) · Mastra live-eval sampling = heartbeats · red-team assertion pack gates External-band validation.
- **P4**: Voice Command Center = cross-surface (desktop/browser/mobile, per-platform capability subsets) · browser→desktop delegation (privileged native ops via `delegations` + ephemeral grants, through pipeline).
- **P5**: capability versioning = Zapier-style single-live + auto-demote-prior-to-available · rollback = fork-from-history, never in-place revert (append-only) · in-flight runs survive capability revision via version markers/step memoization.
- Agents (all phases): star topology — Chief of Staff sole router, NO peer handoffs · hard chain-depth cap + best-so-far fallback · per-agent memory file w/ size ceiling · autonomy ramps DOWN from 100% review (CrewAI 2B-workflow evidence).

## Roadmap v2 ingest (2026-07-06 — ADD-ONs to phases, NOT replacement; verbatim: [../raw/roadmap-v2-universal-commons.md](../raw/roadmap-v2-universal-commons.md))
- **Five platform agents** (only permanent ones): Chief of Staff (sole router, v1 DONE) · Learning (never executes) · Communications (draft-only default, egress-gated) · Governance (enforces rules; auto-approves MINOR changes per dual-axis; moderate/major = human ONLY) · Capability Builder. Everything else generated + governed.
- **workflow/skill/agent/tool = PEERS** (user call 2026-07-06). Promotion ladder = trust/evidence ladder, NOT type mutation. "Responsibility" = standing mandate (scope + trigger) attached to agent, bounded by governance rules everywhere (no separate autonomy ceiling).
- **RAG knowledge layer** (P1–P2): personal / workspace / external sources. Graph = source of truth, vectors assist. External retrieval through governed egress only.
- **Universal Commons**: cloud service, generalized capability knowledge ONLY (archetypes, blueprints, governance heuristics, adapters, onboarding Qs). NEVER: memories / docs / emails / names / raw captures / field values. **Commons v1 = curated human-published package registry** (format = ADR-018) — absorbs old P5 publish + P6 marketplace. Mining later; convergence threshold N = **10% of users ≤100 · 5% ≤500 · 1% ≤2000 · 0.1% after** (user call). Contribution = External band by definition (trifecta) → human reviews exact artifact. Commons = update/distribution channel (iPhone-updates model); every surface functions independently offline.
- **Control plane centralization (user call)**: onboarding on ANY surface (mobile/desktop/web), all connected through cloud. Pushback recorded: sync/identity/registry = "Bridge Cloud" control plane, SEPARATE service from Commons — Commons must never hold per-user workspace data or privacy promise dies.
