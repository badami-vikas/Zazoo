**Product** = Living Software: adaptive workspace platform, Kernel→Compiler→Runtime→Generated
Workspace. One platform; **mix-and-match add-on capability packages = the SKU** (DealPilot/Helpdesk/
Recon, Pi-extensions model). NOT a CRM / task manager / static app.

**Users** = professionals + teams (team-pilot P2). **Problem** = static software can't follow how
work actually changes; Bridge learns → generates → evolves, governed.

**Scope** = roadmap P0-P6, honest status per [roadmap](roadmap.md): P1 DONE · P2 slice-1 done (Recon
not repackaged) · P0 in-progress · P3-P6 designed-only.

**Non-goals**: no CRM framing · never vs OS vendors · Commons NEVER holds user data · competitors
researched live, never hardcoded.

**Success criteria** = each phase's "proves X" hypothesis (kernel represents work → generates
software → generated beats static → improves itself → natural interaction → many softwares one
engine → compiler generalizes).

**Key risks**: 4 open security HIGHs ([BUGS](../BUGS.md)) · schema v2 punch-list unscheduled ·
macOS-only coverage · manifest supply-chain gaps block OSS ingestion.

**Open commercial questions (UNOWNED — flagged, not invented)**: pricing/GTM · prototype→kernel data
migration · Bridge Cloud control-plane spec.
